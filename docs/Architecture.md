# Core port architecture

## Boundaries

The Swift AppKit application owns peer discovery, passwords, authenticated network audio, mixing, playback and capture. Plugins never open a routable network socket: their UDP socket binds only to IPv4 loopback and accepts replies only from loopback port 47831.

Swift's network/mixing queue owns its sockets, stream decoders, replay memory, peer history and claim state. AVAudioEngine callbacks use bounded C single-producer/single-consumer rings. They do not derive keys, allocate packet buffers, log, or perform network I/O. The plugin follows the same separation: its audio callback exchanges samples through bounded FIFOs; its worker handles UDP and resampling. Worker scratch is heap-allocated because macOS thread stacks are small.

The app uses independent Core Audio input capture paths and one AVAudioEngine per selected playback card. Each playback engine consumes the same received mix from its own ring, so device callbacks cannot divide the stream between cards. Core Audio channel maps route stereo to the chosen output pairs on each multichannel card. Device choices are saved by Core Audio UID, not transient numeric device ID. A missing selected UID is an explicit error; the system-default choices are resolved when audio starts. The input path currently requires a 48 kHz hardware rate. Device and direction changes rebuild the audio engines while preserving the network session. Multiple selected physical inputs discard their setup backlog once before sending, then opt into per-input drift correction on the session worker while Keep in Time is enabled. The common cushion follows coherent normalized callback sizes and send packet size; changing callback or packet geometry resets acquisition. Single inputs and generic system/application tap mixes bypass this correction. Receive streams and playback cards have their own drift resamplers. Hardware buffer choices are leased only for active input/playback cards and restored at Stop when unchanged by another application.

## Wire contracts

- Network: `RMND`, version 1, 12-byte little-endian header; UDP 47830.
- Discovery: case-sensitive JSON fields `InstanceId`, `Name`, `AudioPort`, `CanSend`, `CanReceive`; UDP 47821, 1.5-second announcements, 8-second expiry.
- Audio codec identifiers: PCM **1**, Opus **2**, custom-mode stereo Opus **3** (64 or 128 frames). PCM frames are encrypted whole, then split behind the six-byte multipart header.
- PBKDF2-SHA256: 100,000 iterations. Audio salt `RemSound.v1.audio-key`, 32 bytes; fingerprint salt `RemSound.v1.fingerprint`, 8 bytes.
- AES-256-GCM wire layout: nonce (12), tag (16), ciphertext. CryptoKit's default combined representation is not the wire layout.
- Plugin: `RSBR`, version 1, 16-byte header; UDP 47831; 48 kHz stereo float audio. Retired message types 2 and 5 are rejected. Hello includes the host process ID. Claims include an ask number; replies include round, ask, part offset and total sample count.

The core plugin makes bounded 240-frame requests, so each reply fits one bridge datagram even for a large host buffer. Host audio is buffered/resampled independently. The app also accepts and splits the larger claim replies defined by Windows 6.0. DAW claims now follow mix history through HostTimeKeeper. Accurate phase alignment between independently scheduled plugin instances still needs real-host verification; no such claim is made for this preview.

Optional bridge message 10 reports host callback geometry without changing the hello, claim or audio layouts. Its 12-byte body contains the nominal host sample rate as a little-endian IEEE 754 double, then the latest actual `processBlock` frame count as a little-endian 32-bit integer. Valid rates are 8,000–768,000 Hz and frame counts are 1–1,048,576. The audio callback publishes one lock-free frame count; the worker sends metadata at most once a second while callbacks are active. Registered instance and endpoint checks apply. Old apps ignore this message, and old plugins leave the observation unavailable. Detailed snapshots distinguish the host block from the 240-frame worker request; observations expire after three seconds. Block duration is derived from frames and nominal rate, not measured scheduling or hardware delay. This observation does not tune or route audio.

## Scope and safety

Audio transmission requires explicit device sending or a plugin's Send parameter. Peers must be locally selected; the remote peer must also select the Mac before accepting its stream. Empty passwords fail closed. Format fingerprints are only comparisons, not authentication; audio and tick proofs must pass GCM verification. Packet lengths, channels, codec IDs, multipart sizes, stream counts and peer counts are bounded.

The bridge has no password because it never leaves the host. The remote-facing socket does not dispatch bridge messages. Relay groups and the server metronome use RemSoundJam. Remote volume/mute commands require explicit profile opt-in, mutual peer selection, authenticated payloads and replay checks.

Each device and plugin sender gets a fresh stream ID when it starts; authenticated low sequence numbers can also recover a decoder after a sender restart without changing the wire format. Incoming streams are decoded separately and mixed by peer. Mac output monitoring is independent of network receiving for DAW plugins. Claims suppress a peer in direct playback; inactivity, explicit release and goodbye restore direct output when monitoring is enabled. A saved single-peer choice retains its address, not its list position.

## Tests and remaining acceptance

`Source-and-tests.md` lists every test suite, the Mac simulator among them, and how to run each.

Swift tests cover the original C# golden vectors, encryption failure, tick UUID byte order, codec/format/header layouts, malformed bridge input, discovery keys, FIFO bounds, PCM multipart reassembly, Opus fixtures, and real isolated UDP audio/bridge exchange. The C++ suites exercise bridge parsing and FIFO bounds plus the production processor's audio, resampling, state and peer-reordering behavior.

The app's native accessibility check validates field labels, native button-cell roles, explicit key order, a selectable status message and sending-off defaults. It does not prove VoiceOver announcements or DAW integration in a real user's session.

Future acceptance includes real cross-machine audio in both directions, plugin receive/release with multiple instances, Logic/other host scans, capture permissions, device changes, sleep/resume, long-running jitter/drift measurements, full keyboard/VoiceOver operation, and physical Intel testing. Preserve the original protocol when adding relay groups and later Windows features.

## Isolated configuration

The executable bootstrap validates launch options and installs its runtime context before SwiftUI constructs AppDelegate. Normal settings forward Apple's UserDefaults behavior; isolated settings use a private atomic property-list file and never fall back to CFPreferences. The Foundation-only RemSoundRuntime package owns options, settings and paths. The app passes that context to Session, ProfileStore, responsiveness logging and temporary PasswordStore instances. Session uses context-specific server identity and logs, and isolated audio, discovery and DAW bridge sockets bind ephemeral ports. Isolated runs cannot change login items, register global shortcuts or check/install updates. Audio capture timestamps and processing are unchanged.

Configuration roots and settings files must be owned by the current user and inaccessible to other users. Symbolic links, including ancestors and dangling settings links, are refused. Failed writes preserve the last in-memory values and report persistence failure; they never write to the normal preferences.

RemSoundRuntime also contains the isolated headless control transport and stable command schema. Its Unix socket requires a user-owned private directory and socket, verifies peer user IDs at both ends, and bounds message sizes, connection time and outstanding work. It refuses existing paths rather than deleting stale sockets. Shutdown removes only the socket it created. AppDelegate enqueues commands on its main thread and claims the cancellable execution lease immediately before calling existing UI handlers. Expired queued actions cannot start later; a timeout after an action starts reports that its outcome is unknown. Action arguments and status fields are explicitly allowlisted. Transport redaction is an additional safeguard, not permission to return arbitrary settings or credentials.

The bootstrap completes a control-client invocation before constructing any runtime or delegate. Headless startup requires explicit isolated configuration, stays stopped and silent, and starts its control socket after constructing the hidden native controls. It never restores automatic connections or requests permissions. Visible handoff changes presentation and implicit silence, while retaining configuration isolation and disabled ambient services. Main window, Preferences and Server entry points release headless presentation when a person opens them. Headless termination skips interactive profile questions only within its isolated runtime; visible termination retains the normal confirmation flow. Isolated sessions cannot broadcast into normal LAN discovery. GUI-only operations and the Windows reflective control surface remain outside the current command subset.

The stable isolated controls also select advertised channel pairs, tune codec/receive buffering and request server connection or self-monitoring through the existing controllers. Pair indices are zero-based. System-device commands account for the extra All row. Headless server and feedback-warning entry points defer when the visible notice has not been acknowledged with its saved suppression choice. A desired self-monitoring off request invalidates any earlier queued readiness callback, preventing a late on response from undoing it. Server status exposes only connection/self-monitoring booleans, not arbitrary server or profile text.

Profile commands reuse the native menu's private persistence helpers and ProfileStore. Selecting a profile uses its UUID, never a supplied path. Switching refuses a running or starting session and preserves unsaved writable work; read-only overwrites retain the existing confirmation policy. List replies explicitly expose bounded profile titles and identifiers, while ordinary status exposes only the active identifier, read-only state and unsaved-change flag. Selection never loads Keychain passwords or starts a headless connection. Profile deletion remains a visible confirmation workflow.

Recording controls call the native recorder's private destination helper and the existing Session recorder. Runtime isolation fixes the destination beneath the private configuration. SessionView now exposes recordingFinishing, backed by a Session-worker count of outstanding recording finish groups; stopped capture is distinct from drained disk writers. Headless quit requires a stopped session and no finishing groups, so it cannot terminate a live recording request. JamView additionally exposes metronomeMuted, passed from ServerMetronome's existing local mute state; its initializer defaults preserve existing callers. These public observation fields cross the Core/App module boundary without changing persisted data or wire formats. Metronome controls use JamController, preserve follower-local toggle semantics, validate advertised choices and refuse hidden solo notices. Audio-off relay tests verify requests and roles while deliberately withholding an unmeasured server click schedule.

The asynchronous Session.shutdown(completion:) contract stops audio on the session worker and invokes its completion on the main queue only after recording writers, native callback retirement and notification consumers drain. Pending asynchronous shutdown temporarily retains the Session; completion releases that retention. Final release without shutdown transfers only capture resources to a bounded cleanup owner on the original worker and finishes active recording files without resurrecting the Session. AppDelegate uses terminateLater so writer callbacks can run, and starts the verified updater helper only after that completion. A 20-second timeout cancels termination and discards a pending update without forcing unfinished writers to exit. Repeated quit requests share the pending termination; accepted termination also invalidates a pending permission-dependent session start. The existing synchronous shutdown remains available for engine teardown and does not promise recording-drain completion.

UpdateCommand is the Core/App/helper boundary for bounded subprocess output and deadlines. A nonblocking pipe drains both streams; timeout or output overflow first terminates its own subprocess, then kills that exact subprocess after a short grace period if necessary. The helper limits the whole command sequence to six minutes and individual tools to at most one minute; app preparation allows cleanup before its seven-minute outer deadline. Native failure alerts deliberately remain until dismissed. Recovery starts only after a valid install request observes the old app exit, so malformed arguments never delete a cache stage, reopen the app or display a failure dialog.

UpdateArchive owns the fixed four-bundle layout, safe version, bounded raw unzip/zipinfo metadata checks and native extraction through the separate UpdateSupport C target. Raw type checks remain necessary because system libarchive can normalize FIFO metadata. The seekable ZIP reader permits no outer filters, links or automatic disk extraction. It bounds compressed reads, actual output before each write, 10,000 headers and created files/implicit directories, path length/depth, duplicate/case aliases, declared-versus-actual sizes, CRC and monotonic elapsed time. Parent descriptors and exclusive no-follow file creation keep archive paths inside a fresh owner-only root. Failure cleanup checks the created root identity and never deletes a pre-existing directory or symlink. C deadline checks cannot interrupt a blocked kernel I/O operation; the outer helper process deadline remains independent. Actual bundle/version, Developer ID, notarization and universal-architecture checks remain mandatory after extraction and before/after transactional replacement. Seekable libarchive indexes the central directory before yielding entries, so its caller header limit does not independently bound that index. Both raw commands must finish successfully within the combined-output and time budgets, and the validated listing must stay within the path and entry limits, before native extraction starts. Bounded malformed-count and large-index tests refuse those archives at this preflight boundary. The non-indexing reader was evaluated but loses central-directory executable permissions and does not support ordinary data-descriptor entries under the current strict size contract; retain the seekable reader and its mandatory preflight together. These checks do not sandbox a hostile same-user process that replaces the archive between inspections. A complete signed matching update/install/rollback/reopen cycle is still unverified.

Ordinary app formats are announced immediately before that stream sends samples, then refreshed during active sending. Idle enabled sources create no format-only lane. A custom-only input destination receives only its custom stream; destinations without custom support still receive the ordinary input stream. Empty plugin audio messages are ignored. Heartbeat authentication and capability negotiation remain independent of source activity. The wire format and lane identifiers are unchanged.

Route diagnostics use a spare connected IPv4 UDP socket to read the kernel-selected source address, map it to a BSD interface and read its SystemConfiguration type. No packet is emitted and no interface is configured. A utility worker performs the lookup; the session worker only requests it and logs initial routes and changes. At most one lookup batch is pending, including across stop/restart, with a five-second refresh interval and generation checks to discard stale results after destination changes. These observations cannot establish historical routing or per-packet delivery. Audio callbacks never perform this lookup or file logging.

AudioSupport provides a preallocated capture-wake primitive attached before starting eligible direct built-in microphone capture. It coalesces complete-packet notifications through a nonblocking pipe using lock-free state. The Session worker enables it only for one push-driven physical source with sending and a selected destination; packet geometry follows the actual ordinary/custom lane. Professional interfaces, multiple inputs and unavailable notifications retain the independent 1 ms timer fallback. Generation checks reject retired events.

The native wake context optionally records the first and latest eligible signal timestamps. Coalescing preserves the first timestamp; consumption calculates both ages before rearming. Timing uses preallocated lock-free counters and a monotonic clock. If the timing metadata is unavailable, the notification still works without age observations. The attachment observes consumed figures on the serial owner before invoking its ready handler, and retired generations do not report or send. AudioSupport and its Swift callers are compiled together; this snapshot extension does not change network or plugin bridge messages.

The serial owner records fixed per-interval call counts and elapsed wall maxima for encoding, fresh random nonce creation, authenticated sealing, encrypted layout, wire framing, audio relay routing and UDP sending. It formats one bounded detailed-log line per reporting interval, without retaining a packet trace or logging from an audio callback. Control traffic is excluded from these audio-send counters. Routing includes its nested UDP call; maxima are independent and not additive. Notification ages start at the eligible signal, not capture callback onset, and are unavailable for timer-driven sources. None of these figures is a CPU or end-to-end latency measurement. Encryption retains the same fresh CryptoKit random nonce and authenticated wire layout; scheduling and device ownership are unchanged.

Core Audio copies an immutable callback context containing a strong ring and a whole-callback retirement lease. Stop closes the lease before native stop/unregister; successful unregister and an idle callback are both required before notification memory is freed. Consumer cancellation is a separate barrier. Failed unregister retains the registration and blocks replacement capture, with at most 100 native destroy attempts. Cleanup polling is bounded; exhausted cleanup requires an app restart and never reports safe shutdown. Native errors are reported from the worker, never by file logging in a real-time callback. No shared hardware buffer policy or wire format changes here.

Isolated native-shaped callback tests measured lower send-gap percentiles, with modestly higher process CPU, and exercised failure, recovery and short churn. A nonblocking syscall does not guarantee hard real-time execution; physical interface cadence, acoustic alignment, long sessions and VoiceOver acceptance remain separate checks.
